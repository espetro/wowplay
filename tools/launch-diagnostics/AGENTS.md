# launch-diagnostics Package - Agent Guide

## Overview
Parse Wine launch logs and emit structured diagnostic verdict. Enables automated iteration on WoW.exe launch failures without manual log inspection.

## Your Workspace
```
tools/launch-diagnostics/
├── AGENTS.md          # This file
├── classify.py        # Main CLI: log → verdict JSON
└── __pycache__/       # Python cache (ignore)
```

## Quick Start

### Classify a Launch Log
```bash
# Classify latest log (auto-detected from data/launch/)
python3 classify.py

# Or specify explicit logfile
python3 classify.py /path/to/wine_launch.log

# Output: JSON verdict
{
  "stage": "graphics_init",
  "winerosetta": "active",
  "signatures": ["dxvk_wrapper_loaded", "x87_patch_injected"],
  "hints": ["GPU initialization started", "awaiting graphics device"],
  "evidence": ["timestamps": [...], "backtrace_indices": [...]]
}
```

## Purpose

**Automated launch diagnostics**: Given a Wine launch log, determine:
1. **Stage**: How far did WoW.exe get? (dll_missing → graphics_init → x87_crash → crashed → login_screen)
2. **WineRosetta active?**: Was the DLL injection successful?
3. **Key signatures**: Which subsystems initialized?
4. **Evidence**: Exact log lines and timestamps that support the verdict

This enables `scripts/iterate-launch.sh` to programmatically decide next steps (retry, debug, skip).

## Verdict Stages

| Stage | Meaning | Next Action |
|-------|---------|-------------|
| `dll_missing` | winerosetta.dll not found or failed to load | Check build artifact, PATH |
| `graphics_init` | DXVK/graphics subsystem starting | OK, wait for more |
| `x87_crash` | x87 instruction caused CPU exception | Check x87 corpus, add instruction |
| `crashed` | Unhandled exception, stack trace available | Analyze backtrace |
| `login_screen` | WoW initialized fully; login screen rendered | Success |

## Usage

### In scripts/iterate-launch.sh
```bash
#!/bin/bash
VERDICT=$(python3 tools/launch-diagnostics/classify.py "$LAUNCH_LOG" --json)
STAGE=$(echo "$VERDICT" | jq -r '.stage')

case "$STAGE" in
  login_screen)
    echo "✓ WoW launched successfully"
    exit 0
    ;;
  dll_missing)
    echo "✗ winerosetta.dll not found; rebuilding Zig..."
    zig build
    ;;
  x87_crash)
    echo "⚠ x87 crash detected; check instruction corpus"
    grep -A5 "x87_crash" <<< "$VERDICT"
    ;;
  crashed)
    echo "✗ WoW crashed; analyzing backtrace..."
    jq '.evidence.backtrace' <<< "$VERDICT"
    ;;
esac
```

### Standalone Diagnostics
```bash
# Interactive exploration
python3 classify.py /var/log/wine/launch.log --verbose

# JSON for processing
python3 classify.py /var/log/wine/launch.log --json | jq '.signatures[]'

# Multiple logs (batch)
for log in data/launch/*.log; do
  python3 classify.py "$log" --json
done | jq -s 'group_by(.stage)'  # Group by verdict
```

## Data Flow

1. **Wine launch logs written to**: `data/launch/` (gitignored, generated by `launch-wow.sh`)
2. **Classified by**: `tools/launch-diagnostics/classify.py`
3. **Output to**: stdout (JSON) or optionally `data/launch/verdicts.json`
4. **Consumed by**: `scripts/iterate-launch.sh` (automated loop), developers (manual inspection)

## Key Signatures

### DLL and Injection
- `winerosetta_dll_loaded`: DLL entry point called
- `x87_patch_injected`: Silicon patch activated
- `hook_injection_success`: Hooked function calls detected

### Subsystem Initialization
- `dxvk_wrapper_loaded`: DirectX/DXVK loaded
- `gpu_device_enumerated`: GPU detected by DXVK
- `d3d9_initialized`: Direct3D 9 surface created
- `audio_subsystem_ready`: DirectSound initialized

### Crashes and Errors
- `cpu_exception`: CPU fault (often x87 invalid instruction)
- `segmentation_fault`: Memory access violation
- `unhandled_exception`: C++ exception not caught

## Implementation Notes

### Heuristics
- **Stage detection**: Sequence of log keywords (e.g., if "DXVK" appears before crash, stage = graphics_init)
- **WineRosetta detection**: Presence of injected hook addresses in backtrace or function call logs
- **Confidence scoring**: Higher confidence if multiple signatures match

### Edge Cases
- Partial logs (truncated mid-initialization): Assume last stable stage + warn
- Multiple crashes: Report first crash stage, list all crash signatures
- No recognizable output: Verdict = `unknown` with raw log excerpt
